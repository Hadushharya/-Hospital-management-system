# Hospital Management System — full scaffold (Steps 1–10)

Built against the confirmed workflow: parallel lab dispatch (OPD sends to Reception
+ Lab simultaneously), Store Man as inventory-only staff, service fees via Reception
(`Invoice`) vs. product fees via Cashier (`Payment`), real-time auto stock deduction
on dispense, and payment method (Cash / Bank transfer) on every money-collection point.

## Honest limitations — read this first
This sandbox has **no .NET SDK and no NuGet registry access**, so nothing here has
been compiled, restored, or run. Every file was hand-written to match what the real
tools would produce. Before trusting this against real data:

1. Open in Visual Studio 2026, let NuGet restore, and **build**.
2. Fix any compile errors (there may be a few — 30+ hand-written files without a
   compiler checking them is exactly the situation to be careful about).
3. Only then generate the real migration (see below) and run it.

`Scripts/InitialSchema_Reference.sql` is a plain-English/T-SQL sketch of the schema
for your own review — it is **not** a real EF Core migration and should not be run
directly against a database you care about. Real EF Core migrations need a
Designer.cs + model snapshot generated by `dotnet-ef` against the compiled assembly,
which I can't produce without the SDK.

## Setup on your machine

```bash
# from the HospitalManagementSystem/ folder (the one with the .sln)
dotnet restore
dotnet build
```

Update `appsettings.json` → `ConnectionStrings:DefaultConnection` to point at your
SQL Server 2025 instance, then:

```bash
cd HospitalManagementSystem
dotnet tool install --global dotnet-ef   # if not already installed
dotnet ef migrations add InitialCreate
dotnet ef database update
```

This creates all tables: Identity (`AspNetUsers`, `AspNetRoles`, ...) plus the 13
domain tables from the ERD (`Patients`, `Visits`, `Invoices`, `Triages`,
`Consultations`, `LabRequests`, `LabResults`, `Prescriptions`, `PrescriptionItems`,
`Payments`, `Medicines`, `MedicalGoods`, `StockTransactions`, `Suppliers`).

## What's implemented, module by module

| Module | Controller | Notes |
|---|---|---|
| Reception — register patient | `PatientsController` | Creates Patient + Visit + paid Registration invoice in one step |
| Reception — billing queue | `InvoicesController` | Collects the Lab fee invoice a doctor generated; confirms payment so Lab can proceed |
| Triage | `TriageController` | Queue of visits with no triage yet; records vitals |
| OPD | `ConsultationsController` | Consultation + branching into lab request and/or prescription (both from one consultation, confirmed) |
| Laboratory | `LabRequestsController` | Only shows requests where `Invoice.Status == Paid`; enters results |
| Store Man | `MedicinesController`, `MedicalGoodsController`, `SuppliersController` | Item registration with full metadata; every registration logs a `StockTransaction` (StockIn) |
| Cashier | `PharmacyController.PendingPayments/CollectPayment` | Product-fee payment, with Cash/BankTransfer choice |
| Pharmacist | `PharmacyController.ReadyToDispense/Dispense` | Auto-deducts stock in real time on dispense, logs `StockTransaction` (StockOut), flags low stock |

## Payment method
Added `PaymentMethod` enum (`Cash`, `BankTransfer`) to both money-collection points:
- `Invoice.PaymentMethod` — Reception (registration, consultation, lab fees)
- `Payment.PaymentMethod` — Cashier (medicines, medical goods)
